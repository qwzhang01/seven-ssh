## 三、技术风险与应对

| 风险 | 可能性 | 影响 | 应对措施 |
|------|--------|------|---------|
| xterm.js 在 Tauri WebView2 中的兼容问题 | 中 | 高 | Phase 0 PoC 验证；备选方案：原生终端组件 |
| russh 库功能不全或有 Bug | 中 | 高 | 关注 issue；备选：thrussh 或 libssh2-rs |
| 云同步工期超出预期 | 高 | 中 | 可拆分为 MVP（仅基础同步）+ 增强版 |
| 跨平台 UI 一致性难保证 | 中 | 中 | 使用 CSS 变量 + 双平台 CI 自动截图对比 |
| 大文件 SFTP 传输卡顿 | 低 | 中 | 分块传输 + 异步 IO + 进度节流 |
| LLM API 费用和响应延迟 | 低 | 低 | 支持本地模型 + 缓存 + Token 限额 |
| Apple 公证审核耗时 | 中 | 低 | 提前申请开发者账号，预留时间 |

## 四、团队配置建议

### 4.1 最小团队（1-2 人全栈）

适合独立开发者/小团队：

```
1 人全栈：   自己前后端全包（约 6 个月）
```

## 七、质量保障策略

### 7.1 代码质量

- TypeScript: ESLint (strict) + Prettier
- Git: Conventional Commits + PR Review
- 代码覆盖率目标: 核心模块 > 70%

### 7.2 测试策略

| 层级 | 工具 | 覆盖 |
|------|------|------|
| 单元测试 | Rust: cargo test / TS: Vitest | 核心逻辑 |
| 集成测试 | Rust: 真实 SSH 连接测试 | 连接模块 |
| E2E 测试 | Playwright + Tauri Driver | 关键流程 |
| 性能测试 | 自定义 benchmark | 传输/渲染 |

```
feature branch → PR → Code Review → merge to dev

dev → release branch → QA → tag → CI 自动发布
```
